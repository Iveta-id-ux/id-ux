# Case study frontmatter schema

Every `*.mdx` file in this directory must declare frontmatter at the top. The schema is enforced at build time via Zod (see `src/content/types.ts`); invalid frontmatter throws a clear error in the dev server.

## Fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `slug` | string | yes | URL-safe; matches `/^[a-z0-9-]+$/`. Used as the route segment: `/work/{slug}`. |
| `title` | string | yes | Display title. |
| `status` | enum | yes | One of: `shipped`, `in_production`, `archived`, `case_study_pending`. Drives status pill color. |
| `case_study_number` | int | yes | Used for the `// case_study_NN` kicker. |
| `hero_image` | string | no | Path to the hero image (e.g. `/images/case-studies/foo/bar.jpg`). If absent, card and page fall back to the corner-bracket placeholder. |
| `scope.role` | string | yes | e.g. `senior_ux`, `lead_designer`. |
| `scope.team_size` | int | no | Numeric team size. |
| `scope.duration` | string | yes | e.g. `18_months`. |
| `scope.year` | int | yes | Year shipped or launched. |
| `scope.industry` | string | yes | e.g. `travel`, `fintech`. |
| `stack` | string[] | yes | Tools used (`figma`, `miro`, etc.). |
| `punchline` | string | yes | 2–4 sentence summary surfaced on the card. |
| `metrics` | array | no | `{ value, unit?, label }`. Hidden if empty. |
| `taxonomy` | string[] | yes | Filter tags. e.g. `travel`, `b2b`. |
| `order` | int | yes | Sort order (ascending) within `featured` group. |
| `featured` | bool | no | `featured: true` cards sort first. Default `false`. |
| `last_updated` | string | no | ISO date. If absent, the build date is used. |

## Status pill colors

| Status | Color token |
|---|---|
| `shipped` | `--terminal-green` |
| `in_production` | `--terminal-yellow` |
| `archived` | `--muted-foreground` |
| `case_study_pending` | `--muted-foreground` (dim "pending") |

## Body conventions

Use `##` for top-level sections (Context, Research, Strategy, Artifact, Outcome). The left rail nav reads section titles from `<h2>` IDs, which are auto-generated by `rehype-slug`.

Use `> // TODO: ...` blockquotes for in-progress notes — they render visibly on the page so the user's editing pass doesn't miss them.
